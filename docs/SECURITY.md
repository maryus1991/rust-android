# Security model

1. **No IPC for remote sites by default.** Capabilities (`src-tauri/capabilities/`) contain no core/plugin permissions. The only grant is
   `allow-bridge` (one app command) and only for the configured origins (`remote.json`, generated by `build.rs`; a unit test checks it equals the runtime policy).
2. **Allowlisted bridge.** `bridge` accepts `{action, payload}`. Every call re-checks the page URL (exact host match, scheme, port, no credentials),
   then looks the action up in a static table that fixes the allowed origin kind (remote/local) and the required feature flag. Unknown actions fail.
   Provided actions: `page.ready`, `page.keepalive`, `app.info`, `network.status`, `network.retry` (local pages only), `app.openExternal`,
   `clipboard.writeText`, `notification.permission|request|show`. There is deliberately **no** file system, shell, HTTP, clipboard-read or arbitrary plugin access.
3. **Exact origin validation.** Hosts are parsed with the `url` crate and compared exactly or by strict `*.suffix`; never by `contains`.
   Tested against look-alikes (`example.com.evil.com`, `evil.com/?https://example.com`, `user@host`, ports, trailing dots, `http`).
4. **HTTPS enforcement.** `security.httpsOnly` (default true) makes `http:` origins never match. TLS errors are never bypassed (no `danger_*` options).
5. **Navigation policy.** Out-of-scope `http(s)` links open in the system browser (or are blocked). `javascript:`, `data:`, `file:`, `content:`, `intent:`, `ftp:`, `vbscript:` are always
   blocked. `tel:`/`mailto:`/`sms:` and `paymentSchemes` open externally only when their features are enabled. `blob:` is allowed only when it was created by an allowed origin. External opens are rate limited.
6. **Permissions** (camera, microphone, geolocation) are denied unless the origin is allowed **and** the feature is enabled; then the decision is handed to the platform's own consent flow. Everything else (clipboard-read, MIDI, notifications API, screen capture...) is denied.
7. **Downloads (desktop)** are saved to the Downloads folder with sanitised, de-duplicated names (no path traversal, Windows reserved names handled).
8. **Secrets** never enter the repository: signing material lives in GitHub Actions secrets; `validate.sh` and the tests scan for key material; `.gitignore` excludes keystores/certificates.
9. **Supply chain.** Rust toolchain pinned (`rust-toolchain.toml`), `Cargo.lock` committed and used with `--locked`, Tauri CLI pinned, workflows use least-privilege `permissions`
   (`contents: write` only in the release job), user-controlled values are passed via `env:` and never interpolated into shell. `cargo audit` runs in `validate.yml`.

Known residual risks are listed in LIMITATIONS.md (e.g. Linux consent prompts, sub-frames, WebView-level behaviour).
